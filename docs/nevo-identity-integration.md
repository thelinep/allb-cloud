# NEVO identity integration

Pinned source: `thelinep/nevoeos` commit `f50af9dd91b987080faa8fa00f2416b73cf8de78`; inspected `prisma/schema.prisma` and `apps/web/lib/nevo-auth.ts` through GitHub. This is a server adapter, not a deployed login service.

NEVO's `User` has a CUID id, optional organizationId, role enum, ACTIVE/SUSPENDED status and emailVerifiedAt. Its Session has tokenHash, userId, expiresAt and createdAt. It does **not** carry credentialVersion, revokedAt or MFA verification evidence. NEVO's existing cookie resolver therefore cannot be promoted directly into an ALLB privileged session. NEVO cookies are not accepted by this bridge, password hash formats are not converted, and users are not matched by email.

`packages/nevo-identity-adapter/adapter.mjs` calls ALLB's existing transaction-scoped authorization guard. ALLB account disablement, credential-version change, revoked/expired session, workspace membership and action checks remain authoritative. It then locks an explicit provisioned identity mapping and the NEVO User row in that same transaction, rejects missing/disabled mappings, suspended/unverified users and organization mismatches, and intersects NEVO role permissions with the authenticated ALLB membership. SUPER_ADMIN maps conservatively to admin, never owner; ADMIN → admin; PRODUCER → editor; FINANCE → reviewer; other known roles → viewer. Unknown roles deny. ADMIN, SUPER_ADMIN and FINANCE additionally require fresh ALLB MFA evidence (15-minute limit).

The mapping DDL in `packages/nevo-identity-adapter/schema.sql` is optional and not automatically applied. It requires both schemas in the same PostgreSQL database, foreign keys to actual identities/memberships/workspaces and NEVO User/Organization tables, and explicitly audited administrative provisioning. Existing separate databases cannot use this transaction adapter without an architecture decision. No application endpoint is wired to it yet. Trusted operation callbacks must constrain subsequent NEVO queries to `context.nevoOrganizationId`; the adapter does not rewrite arbitrary SQL or replace endpoint-level row scoping.

`node tests/nevo-identity-adapter.test.mjs` validates the bridge against disposable PostgreSQL via PGlite, not mocked query results: valid mapping, MFA missing/stale, SUPER_ADMIN downgrade, denied CLIENT/GUEST/VENDOR/STAFF publish, unknown role, disabled/unverified user, incorrect tenant/workspace, missing mapping, mapping revocation, account disablement, credential-version change and session revocation. It does not certify production PostgreSQL concurrency, HTTP cookies/CSRF, login/recovery/MFA enrollment, or remote schema migration. Those remain release gates.

## Imported platform packages and compatibility checks

The supplied original `packages/platform-auth-core` and `packages/platform-mfa` sources are now inspectable alongside this adapter. The genuine auth-core exports generate 32-byte opaque base64url sessions and SHA-256 hashes; a generated token hashes identically through ALLB's guarded `sessionTokenHash`. This proves hash compatibility, **not session authority or cookie migration**.

The genuine NEVO scrypt export stores `<32 hexadecimal salt characters>:<128 hexadecimal hash characters>`, uses the hexadecimal salt as a string and Node's default scrypt parameters. ALLB stores `scrypt:v1:<salt>:<hash>`, feeds raw salt bytes, and explicitly uses N=131072/r=8/p=1. Merely prepending `scrypt:v1:` destroys compatibility. Tests verify a genuine NEVO hash succeeds in its own verifier, fails for a wrong password, and is rejected by ALLB's verifier. No password hash is converted or imported. A future credential migration needs explicit algorithm metadata and verified rehash on successful login, or account recovery; it must increment ALLB credential version and invalidate previous sessions in one transaction.

The genuine MFA package supplies WebAuthn configuration, challenge persistence delegates and SimpleWebAuthn wrappers with required user verification. It does not automatically add MFA evidence to the NEVO Session model. Tests verify disabled-by-default behavior, exact HTTPS origin/RP matching and rejected non-HTTPS/mismatched RP configuration. Challenge delegate tests prove missing/already-consumed candidates deny; they are contract checks, not database concurrency or physical authenticator verification. Future integration must bind the verified ceremony to the existing ALLB user/session and challenge, persist `mfa_verified_at` only after successful server verification, handle credential counters/revocation and retain strict origin validation. Copying imported WebAuthn credentials alone does not satisfy MFA.

Final verification: `node tests/nevo-identity-adapter.test.mjs` passes **23 PGlite PostgreSQL bridge checks plus 11 imported auth/MFA compatibility assertions** on Node 24.19.0. These TypeScript source imports rely on Node native type stripping. SimpleWebAuthn ceremony, physical authenticator, deployed cookie behavior and password migration remain untested/unimplemented.

The privileged bridge also rejects MFA evidence older than the current authentication timestamp, and future authentication timestamps. FINANCE with an ALLB reviewer membership is explicitly covered so this check does not depend on ALLB admin-role enforcement.

`node tests/nevo-identity-browser.mjs` passes 18 actual Chromium desktop/mobile-emulated checks using an isolated two-tenant HTTP harness and disposable PostgreSQL. Each tenant signs in with genuine ALLB credentials and receives only its own mapped records; forged authority headers do not defeat cross-tenant denial; hostile mutation origin is rejected; active-session revocation yields 401. Secure HttpOnly SameSite cookies are inspected. This is test-fixture evidence, not production HTTP endpoint adoption, MFA ceremony, physical mobile certification or deployed Cloudflare evidence.
