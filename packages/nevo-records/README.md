# Durable event and scene records

Migration `003_event_records.sql` extends the existing PostgreSQL tenant schema. Event heads use optimistic revisions, immutable event/scene snapshots, composite tenant references and audit appends. `eventRecords` is a trusted server transaction repository: call it inside `withNevoIdentity` or `withAuthorizedWorkspace`, never with browser-supplied authority. `createEventService` applies the own-auth boundary; pass the NEVO authorizer to additionally intersect NEVO roles.

Commercial services may lock an event head, perform domain validation, append scene/approval evidence and save the head in one transaction. `expectedRevision` refers to the storage revision, starting at 1; the domain workflow revision is separate. A conflict returns `STALE_REVISION`; no stale write is silently retried. Scene snapshots preserve complete supplied JSON; geometry/schema validation remains the domain service's responsibility. Record size is limited to 1 MB. Content digests recursively sort object keys, preserving array order, so PostgreSQL JSONB key ordering does not affect them; they are not signatures or external integrity attestations.

`node tests/nevo-records.test.mjs` verifies authenticated tenant scoping, immutable history, injected rollback, stale optimistic writes and close/reopen durability on disk-backed PGlite. PGlite serializes transactions, so the collision test does not certify networked PostgreSQL lock behavior or production load.

For actual Next HTTP verification, explicitly set `ALLB_LOCAL_DATABASE_DIR` to an absolute directory provisioned separately by a test helper. This is a single-process Node validation backend. It is rejected in Worker runtime, is not an automatic fallback, and never auto-migrates or seeds data. Configuring it together with `ALLB_NEVO_DATABASE_URL` fails closed. The production PostgreSQL path is unchanged. `tests/helpers/nevo-local-fixture.mjs` creates disposable two-tenant, eight-actor fixtures with real hashed credentials and encrypted TOTP factors; it must not be used to provision customers.

Remaining release gates: reviewed production migration runner/schema tracking, least-privilege DB credentials and verified networked PostgreSQL concurrency, backup/restore, tenancy constraints across the full NEVO Prisma schema, performance/load and controlled staging rollout. No production migration or external service was performed.
